Record shape for the build team

This is the field set the prototype runs on. Whoever builds the SharePoint list or Dataverse table can take it as the starting schema — the front end reads exactly these keys.

{
  "id":            "sub-014",
  "title":         "Leave Triage",
  "tagline":       "Reads leave requests against team coverage rules…",
  "businessUnit":  "People & HR",      // fixed list of 4
  "problem":       "Managers approve leave without visibility…",
  "how":           "Pulls the team roster and approved leave…",
  "demoUrl":       "https://…",
  "thumbnailUrl":  null,                 // null → generated pattern
  "submitter":     { "upn": "…@oskgroup.com", "name": "…" },
  "team":          [ { "upn": "…", "name": "…" } ],
  "status":        "submitted",          // draft | submitted | approved | rejected
  "award":         null,                 // null | winner | runner-up
  "submittedAt":   "2026-10-02T09:14:00+08:00",
  "updatedAt":     "2026-10-02T09:14:00+08:00"
}

Two notes worth carrying over. award is null for every record until results day, which is what keeps the winners band off the gallery — no separate page, no redeploy. And status is what gates visibility: only approved records ever reach the public gallery.
